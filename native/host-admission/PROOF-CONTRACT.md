# Native primitive source interpretation

This is source implementation guidance for the existing BLUEPRINT-003 primitive boundary, not a completed producer, independent source review, native qualification or execution authority. The full product and its native custody integration remain unfinished.

The primitive retains all eleven existing fields: kind, platform, objectIdentityDigest, monotonicTick, operation, outcome, bytesSha256, byteCount, mode, relatedIdentityDigest and sourceImageSha256. It adds no kind, operation, field, actor or rights. The source image identifies the actual actor; the service is the sole original stdout/stderr collector, and the independent observer correlates original objects and retained readbacks.

Under the existing closed operation enum and identity-observation clauses, linux.rename_noreplace and win32.rename_noreplace use identity kind only for an independently observed same originally held object across an actual native no-replace rename. A successful rename return is insufficient. The producer must retain the original held object identity, actual source image and monotonic observations, genuine prior related observation, original parent-directory custody, nonoverwrite result, held before/after identities and the original no-follow reopened target correlation. It must preserve the original native operation/raw captures. Missing correlation remains unresolved and cannot become successful identity, namespace or atomicity proof. Discovery, readback, flush, close and ledger observations remain separate obligations.

Rename identity observations have null byte/hash/mode fields. Nonnull mode is limited to identity observations using linux.fstat or win32.security_info and actual observed 0644/0755. Windows mode derives from the exact protected owner-rights DACL, original file attributes and owner SID, and the original effective-owner native execute check; requested modes are not observations. Auxiliary token and access-check bodies belong to original private native custody without widening the primitive enum.

Read/write observations bind the actual bytes observed by that native call, including actual partial transfers. Successful discovery requires the complete canonical inventory; successful ledger observations require the full exact frame. An actual zero-byte read producing EOF has empty SHA256 and byteCount zero. Failure or unresolved operations with no observed bytes retain null byteCount and bytesSha256; they do not invent a successful empty capture. Source-owned references must bind the actual retained bodies and all original object/lifetime correlations before any positive private proof is used.

The native client mapping additionally retains an internal aligned 16-byte reservation state, disjoint from its publication cell, 56-byte copy-event table, immutable raw records, mutable returned data and private snapshot. Its atomic high-water reservation is published before allocating any native/JavaScript copy, and its terminal failure state is published on a validated owning allocator denial. A successful copy event alone cannot account for an attempted allocation that failed before publication. The actual Windows/Linux x64 native layout is source-checked; this internal state adds no public or private proof field, operation, actor or admission authority. The service and independent observer must correlate this same original mapping/state even when no successful set exists, retain the original raw observations/readback, preserve monotonic conservative charge and hold all copies until original authenticated Node-parent physical exit. The actual constructor, failure observation, full accounting and archive integration remain unfinished; these source structures alone cannot establish physical allocation or closure proof.

PA1 original source readers (unfinished owner integration)
-------------------------------------------------------
The private P/G/C readers consume already-held readonly original native objects,
never runtime paths or caller admissions. Native metadata and genuine same-file
read/EOF observations are compared before and after the complete body. Linux
retains actual F_GETFL/F_GETFD/fstat fields, including FD_CLOEXEC. Windows retains
actual GrantedAccess, GetHandleInformation, synchronous IO mode, full FILE_ID_INFO,
owner, size, creation/write/change observations and real read results. Native
rights/owner/file identity are observations, not source authority.

Each source body is an exclusive retained original native view. Ordinary IO
borrow/return paths reject it. Failure retains its original native mapping,
source borrow and accounting charge; no retry or close is inferred. Success
likewise retains it through original provider/caller/source/parser/observer and
bound archive/readback lifetimes. A complete authenticated source-owner terminal
release is still required and currently unconnected. Added metadata must fit the
actual source-owned allocator calibration; a struct declaration is no evidence.

Private grant parsing uses the selected six keys and calibration parsing the
existing thirteen keys. Original measurement files can be hashed using <=16384
existing control scratch through the selected original evidence size bound;
there is no 8MiB control allocation or profile-frame reinterpretation. Every
calibration rawEvidence name/count/SHA/source must match its actual original
native read observation. These checks cannot authenticate a provider or ROOT.

Original Git association comparison hashes actual blob/commit/tree preimages,
compares exact commit-to-tree-to-regular-blob membership and raw SHA256, rejects
extra tree bodies/duplicate names/symbolic or gitlink selected leaves. It does
not invoke Git, enroll a source tuple, accept a self-issued expected digest or
replace independent original input authority. All borrowed source-packet objects
remain independently authenticated and retained by the required PA1 acquisition
owner before any profile seal or accounting admission. The actual acquisition,
provider/caller, HA2 original key lease, native captures and production engine
remain unfinished. These reader descriptions do not declare completed product
source or qualify a native receipt. No shared proof keys or operations change.

## Selected private handoff, without another application protocol

The proposed implementation of the already selected PA1 capability is a native
original-object handoff from the independently admitted installation/qualification
caller to its independently admitted provider and then the sole service bootstrap.
It uses the existing private native lease API, separate from host/launch/inspection/
Core frames. It adds no shared field/operation, source certificate codec, signing
algorithm or public enrollment entry. A new credential/authority transport would
require a separate whole architecture amendment rather than be hidden here.

The issuer side must first perform its REAL existing credential acquisition and
source/native admission, retaining the original credential objects and issuer
source association. Its consumer-side authorization must name the exact original
caller/provider images, source graph, owner and permitted complete native-input
ROOT. This is the authority step still requiring the original implementation
specified below; no placeholder authenticate() return, Boolean, registry pointer,
self-issued seal or application digest can satisfy it.

After that step, the source-owned installation caller holds the original admitted
source packet, original P/G/Q/C/case/capacity/image objects and original actor
references. It acquires the provider capability once BEFORE service creation,
endpoint/store access, child launch or source input IO. The provider retains the
same caller/credential/issuer/ROOT objects and returns native original references,
not a replaceable path or JSON assertion. The caller and provider are separate
original actors; no arbitrary identity is chosen by this document.

Windows handoff must use actual original process/handle objects and native
DuplicateHandle observations: original process birth/token/image correlation,
original source handle identity and granted rights, actual duplicate return and
receiver same-object observation. Requested access is not observed access. Native
file identities preserve full FILE_ID_INFO and owner SID; source leases preserve
observed readonly rights, inheritance flags and synchronous mode. The original
issuer/provider/caller process objects remain held. Numeric HANDLEs passed in an
application request, argv/environment, an arbitrary parent process or ACL-only
path do not enroll this handoff.

The present Linux kernel_linux.go source has only same-process
F_DUPFD_CLOEXEC duplication; it does not implement a cross-process admission
issuer. The selected private native API can consume and duplicate already
authenticated SAME original references inside its native acquisition owner.
Original retained pidfd/process identity, full fstat, F_GETFL/F_GETFD and source
owner/birth/image observations remain required. If the original issuer/provider
implementation below uses separate processes, its actual authenticated native
handoff source must be supplied and whole-reviewed. A kernel SCM_RIGHTS transfer
is a concrete candidate for that private original-object handoff; it would require
the actual original channel/peer/control-message/descriptor capture and full
source binding, not a new public admission message. It is not yet selected or
implemented here. pidfd_getfd is not selected and grants no ptrace privilege.

An fd number, SO_PEERCRED observation or successful duplicate/transfer alone is
custody, not issuer authority. The duplicate must identify the SAME admitted
original source object; no substitute memfd/copy, reopened user path or synthetic
original ROOT is accepted. The provider owns full duplicate/original disposition
evidence. No additional privilege, kernel feature, provider image or issuer is
granted by this design; unavailable original operations deny and retain. The
actual same-process Windows DuplicateHandle source likewise does not establish
an existing cross-process credential/issuer implementation.

The receiver follows the approved N2 ordered constructor in section3: original
once-only ingress; reserve original source-owned control/capture/initial capacity;
reobserve caller/provider/issuer/image/source objects; verify complete independently
admitted ROOT and genuine Git associations; read SAME P/G/Q/C/case/capacity bodies
to real EOF with actual before/after observations; acquire the separate original
HA2 key lease; check actual image/stack/IO/runtime capacity; register every partial
extent before subsequent failure; transfer SAME owner once into early entry;
retain originals through actual capture/archive readback and terminal disposition.
Ordinary CLI/library input has no route to this private ingress.

Success permits the actual early Node/native service entry only after every
original authority and custody condition is verified. Q32 remains qualification
only; independently admitted measured B0/B2 remains required for production.
Service aggregate1MiB, store4MiB, Core128MiB and complete Windows/Linux public

IO, native buffers, copies and conservative charge; timeout is not closure.

## Explicit corrections of unsupported stronger promises

Original input blueprint A4A3AFC1C0D7509448F2F9B11B22B411556BF2025776FCB28F706399DC9F91F8 promised not to create/delete/change input content. Revised author/report F732354647ACEA1158A2D401025F246449167191394656CCDA02020F079888AB expanded this into unchanged input root and every physical descendant/metadata and guaranteed finite physical IO. Entire feasibility reviewer REPORT explicitly records that original CLI FOUNDATION/full-scope attachments do not demand no-atime, arbitrary namespace acceptance or arbitrary-filesystem real-time syscall completion. Its concerns are valid against those strengthened promises: held POSIX descriptors do not prevent ancestor relocation; close or CancelIoEx does not prove blocked kernel IO completion. Preserve both reports and all failed evidence unchanged.

Selected durable correction is narrow and explicit: source preservation means CLI performs read-only access to the four original candidate asset objects, never rewrites/truncates/renames/unlinks them, never chmods/chowns/changes ACLs or removes their directory, and never uses them as cleanup targets. OS-managed read accounting is not content mutation and is not a no-atime guarantee. Original assets are data, not writer capabilities. Their held copied bytes must match actual independently admitted raw identities before derivation. This does not claim exclusion of another actor's concurrent source mutation; detected changes deny and no path reopen becomes authority. Destination writes use exclusive private candidate creation and exclusive final commit; they cannot overwrite/merge into originals or existing retained targets. Snapshot overlap/identity checks deny visibly overlapping input/output roots, but are diagnostic protection, not a cross-platform proof that arbitrary physical ancestors cannot move. No promise covers every new descendant another actor moves under the input after checks. Native writer never receives source handles or cleanup authority.

Logical time/byte/session limits are enforced independently of child wait/admission locks. A timeout rejects late results, closes channel/listener and prevents a new materialization request; it does not assert finite completion of every arbitrary kernel operation. Held resources remain owned until actual completion. Outstanding IO is recorded as retained/unresolved failure, never released/success. New invocations are denied if they would reuse that owned session/resources; concurrency admission must cap retained sessions, not accumulate stalled work. No blind retry, unknown PID kill or unknown-root cleanup. Actual host/tool/native acceptance must demonstrate terminal closure under the supported admitted filesystem and original protected deadlines; an unsupported/stalled filesystem fails closed. This corrects invented absolute physical guarantees without weakening real original bytes, containment, original-child custody, deadlines or truthful resource closure.

This ADR records that correction explicitly. Whole durable review and governed landing remain required before code. If an owner expressly elects a stricter whole-namespace/no-metadata/finite-arbitrary-syscall requirement, this mechanism does not satisfy it and remains NO-GO until an actual enforceable platform architecture is approved.

## Exact v3 wire grammar and closed operation table

All numeric values are u32 big-endian except explicitly u8 enum/boolean fields. `S` is u32 UTF8 byte length followed by strict UTF8 bytes; `B32` is exactly32 raw bytes. Length arithmetic is checked before allocation. No trailing byte, optional field, decoded duplicate, unknown enum or unspecified phase exists. Domain spellings ending `\0` mean one zero byte. Modes are u8:0=0644,1=0755. Record-name enum u8:0=service-template.tar.gz,1=template-candidate.json,2=template-contract.json,3=SHA256SUMS. Records appear once in that order. Entry count1..128; entries sorted by exact ASCII path bytes; strings use existing portable catalog limits.

The private greeting is binary and versioned with primary/SEA/writer: u32 body length <=512, body `(u8 operation=1,u32 sequence=0,u32 protocol=3,B32 launchNonce,S candidateVersion,B20 fullSourceSha,B32 helperSha256)`, then B32 HMAC. Source SHA is20 raw bytes; version is1..64 ASCII bytes under the existing candidate version grammar. Greeting MAC is HMAC-SHA256 under the inherited32-byte launch capability over `SLCLI-GREETING-3\0` then exact body. SEA validates version/source/helper against embedded candidate identity and original channel; mismatch terminates without READ. This is the sole greeting grammar, replacing old JSON greeting. The ordinary frame MAC is the already selected `SLCLI-AUTHORING-3\0`/direction/nonce/u32 sequence/u32 body-length/raw-body grammar; embedded body sequence must equal envelope sequence. Nonce is obtained only from authenticated greeting. No capability appears in writer input, receipt, stdout or artifact.

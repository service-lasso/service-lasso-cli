# CLI39 private-body route2 feasibility32

Source-only architecture proposal 2026-10-10; no debugger, interception, provider change, target execution or authority is selected by this document. This supplements PRIVATE-PHASE-CONFLICT32 and preserves all full delivery gates.

## Candidate supported mechanism and concrete limit

The supported candidate is an external Windows user-mode debugger owned by the SAME existing native process controller, starting the fixed operation host under DEBUG_ONLY_THIS_PROCESS before its first instruction, with WaitForDebugEvent/ContinueDebugEvent, GetThreadContext/SetThreadContext and ReadProcessMemory. Debug events suspend the affected process threads until continuation. This supplies a documented stopped-process read cut; it does not supply a documented Wintrust allocation/AddPrivateData/free event. Public debug events identify process/thread/module/exception events, not those semantic operations. Therefore this candidate is NOT an implementation-ready complete private-body observer.

An attach after host startup cannot prove pre-allocation coverage. DebugActiveProcess additionally introduces an initial breakpoint and requires suitable process access. A polling reader, heap-event stream, FinalPolicy-entry breakpoint or postreturn helper cannot replace the missing semantic cut. Software breakpoints, injected detours, replacement provider callbacks and modified provider code are excluded from this proposal. Captured pfnAddPrivData2Chain/pfnFree aliases remain data, not calls or permission to intercept.

## Exact coverage that would be required

Before starting the default WinVerifyTrust invocation, the actual authenticated loaded provider implementation would have to supply a complete fixed map of every relevant allocator, private-registration, body mutation, replacement/reallocation and release path, including direct/inlined releases and failure unwinding. Module exports alone cannot establish that map. At the actual registration cut, preserve SAME invocation, thread, provider DATA original, private GUID/ordinal, allocation generation, size and pointer aliases. At each actual body replacement and immediately BEFORE release, while all potential writers are stopped, preserve the actual bytes and required partial/error/disposition evidence. An AddPrivateData call can precede later mutation and is not by itself the final body capture. A pre-free observation proves that read cut, not that the subsequent free succeeded; retain separate resume/return/actual-release evidence. Address reuse must create another generation, never overwrite the earlier original.

No authenticated fixed implementation map or supported provider semantic event interface is present in the selected source. Hardware execution/data breakpoints do not create that map and cannot be assumed to cover arbitrary concurrent private objects or all writes/frees. Single stepping all instructions could expose instruction cuts, but instruction decoding, allocation semantics and complete all-thread coverage would themselves require a fully specified source/input/profile method; no such interpreter or bounded execution count is selected. This document does not propose that as a hidden fallback.

## Ownership, concurrency and lifetime

Core119 confirms the current shared owner has no selected debug-port/CREATE_PROCESS_DEBUG_EVENT/WaitForDebugEvent relation; its existing CreateProcess/job/pipe/attribute ownership remains unchanged. A prospective debugger must extend that SAME controlling owner and its actual creating thread, not add a second process owner, attach helper or generic callback. The fixed CLI operation-host is the debuggee; publisher remains inside it. Every create-thread/load-module/unload/exit/exception event, debug handle, pending continuation and context change would need preowned custody and exact-once disposition. Newly created threads must be covered before they can execute provider code. A stopped event is not permission to close the provider state or declare useful trust.

Default action GUID, WTD flags, installed Microsoft provider bytes and ordinary trust calls would remain unchanged in the candidate. However debugger presence and thread suspension are observable and change scheduling. Default API/provider-byte invariance therefore does NOT establish observational or trust-behavior invariance. Required acceptance must explicitly assess this difference, including debug-sensitive behavior; current source cannot assert equivalence.

## Finite budget, deadline and failures

All debugger stacks, native handles, contexts, event roster, module maps, allocation-generation records, each body copy, partial copies and retained overlap must be disjoint charges inside SAME genuine existing operation/runtime reservation. Capacity must come from authenticated actual profile values, never guessed object counts or a new allowance. SAME original absolute deadline and response apply while the debuggee is stopped; event waits must be bounded by remaining original time and retain raw BOOL/error/timeout separately. A deadline response cannot silently resume past required unread custody, abandon a pending debug event, kill the host, widen the deadline or claim complete capture. Exhaustion, unknown acquisition, read failure, lost debuggee/debugger or uncertain continuation leave required bodies incomplete and retain the original owner/event/process state for its governed failure lifetime. Event-induced all-thread suspension and externally enforced startup deadline also require genuine capability/profile admission; no numeric finite fit is claimed.

Parent selects option A below for durable precode and a fresh independent intent

## Existing contract and exact scope

NODE-MEASURED-FINITE-BUDGET-N2-PRECODE.md section6 states that cookie entropy is
not source/key authority and that startup/security/helper effects remain owned
and charged. The build-owner CONTRACT initial source boundary separately requires
the original admitted engine/native/tool/source/case/profile occurrence, complete
own-actor custody and native outputs before useful continuation. Neither clause
requires predicting random entropy or makes a cookie a credential.

The selected candidate audit in CLI39-INITIAL-WINDOWS-LOADER-EFFECTS-OCT16.md
records exact cl/link/helper TLS/load-config/cookie/delay declarations. Raw PE
directory presence establishes a required format/possible effect case, not that
a cookie is changed at the first event. No child has been executed/observed here.

Microsoft's [Debugging Events](https://learn.microsoft.com/en-us/windows/win32/debug/debugging-events)
documents that the new-process create event precedes user-mode execution and
other debug events for that new process; an event notification suspends its
threads until continuation. The same event code can also describe attach to an
already running process. This proposal covers ONLY actual new child creation
from the fixed owner's retained successful CreateProcessW(DEBUG_PROCESS) call.
DebugActiveProcess/attach, an arbitrary supplied PID, replayed/copied event or
merely matching event code never qualifies. No attach API exists in the closed
emitter table. A stopped read by itself never identifies its writer/source.

## Fixed constructor, native case and permitted output

Planned private site: native/build-owner/initial_windows_cookie.ps1. The only
caller is the fixed initial A birth/module pipeline. New-SlcliInitialWindowsCookieCase
will construct a case from SAME Owner/Birth/Child/PendingEvent and actual mapped
module source originals. It does not accept a case pointer, expected cookie,
JSON, token, boolean, callback, module name or public profile field as authority.

Required joins are the original native CreateProcessW operands/result and complete
actual new-child process/thread handles, PID/TID/creation-time/selected primary
principal/parent correspondence; the first successful native event for that child;
the actual creator native thread; no prior continuation; the immutable original
deadline; and the complete independently admitted initial source/case/profile.
The source-owned actor recipe must account for every product actor/alias with
access to child memory. It contains no child WriteProcessMemory/SetThreadContext,
injection, untracked child or useful callback before this cut. Initial runtime
own actors and inherited aliases still require their full exclusion/custody;
trusted-host external nonmutation does not excuse any product actor. Unknown
writers/case history invalidate construction. No caller-provided mystery original
substitutes for these actual construction steps.

Covered modules are the created main image and any explicitly source-selected
initial kernel-mapped image whose actual mapping and native creation case join
that SAME pre-user-code occurrence. A basename, source-roster position, version,
hash or simple presence in the child cannot make a module eligible. Each joins
its SAME complete held source file/EOF/currentness, actual mapped allocation,
complete source PE geometry and supported IMAGE_LOAD_CONFIG_DIRECTORY64 span.
Unknown initial module cases fail. This does not claim every candidate system DLL
has already obtained its actual source/creation-case join.

Before birth, the source decoder retains exactly the complete load-config size,
the SecurityCookie VA field, preferred image base and checked corresponding
eight-byte in-image source slot. The actual relocated load-config pointer must
equal the independently derived actual module base plus that source RVA. No
outside, truncated, misaligned, duplicate or ambiguously overlapping cookie
slot is admitted. Cookie slots must be disjoint from import binding/relocation
effect targets, TLS index slots, source metadata and all control/output buffers;
no permission is inferred for neighboring writable bytes.

The cookie remains an opaque actual native creation OUTPUT, with full UInt64
raw bytes and provenance. It has no source, key, credential, funding, principal,
ROOT or command-selection role. No statistical/randomness/high-bit/default-value
test can prove its writer. The fixed native case is what attributes the output;
the value is not reverse-engineered into a guessed entropy history.

Two distinct exact eight-byte native captures bracket the full mapped-image
readback, each with separate VirtualQueryEx/ReadProcessMemory operands/results,
complete transferred length, actual allocation/type/protection and before/after
clocks. Same stopped event/creator thread/case/current source/no-writer relation
must survive both. Both raw outputs and the embedded full-image word must agree.
This is a consistency check inside a genuinely constructed case, not proof of
provenance from equality. Failed/short/late/changed/unknown output stays retained.

Final immutable source/relocation/IAT expected bytes remain separate and are
never filled from the observed cookie. Exactly the source-defined cookie output
span is evaluated by its owned native-output relation; every other image byte
still needs its own source/effect rule and comparison. There is no generic mutable
region mask, observed-byte exception list or public expected-value operand.
This proposed typed output relation awaits independent intent review; current
code still refuses unexplained cookie differences.

## Finite cost, aliases and unsupported phases

For C eligible initial module slots, prebirth backing owns two independent
eight-byte native bodies and two64-byte query/read control records per slot
(144C native bytes plus actual arena alignment), fixed source/case/output rows,
managed raw copies and all transitive source/metadata costs. The capacity derives
from the source-selected initial member roster, with at most one load-config
cookie slot per actual module occurrence, never an unbounded discovered list.
Each complete capture phase has one creator-ID native call and2C native query/
read calls, all with the owner's four QPC/frequency calls per API, plus four
processing clocks. Thus both phases cost18+20C actual native calls before
conditional failure paths; source parsing has its separately charged original
clocks and CPU costs. Exact profile/physical fit still must be constructed and
admitted; this formula alone is not a reservation or numerical-fit proof.

Source file handles, mapped image originals, process/thread/native event, cookie
rows, all raw outputs and their buffers remain SAME-owner borrowers through full
source/loaded comparison, eventual native continuation and actual last borrower.
No numeric-handle coalescing, cookie copy, completion flag, GC or delegate return
closes anything. Every failed/pending result retains first cause and native
custody; no retry/new deadline/cleanup escape is introduced.

Later LOAD_DLL events, initial loader breakpoint, TLS callbacks, CRT startup or
any event after prior child user-mode continuation are NOT this pre-user case.
They require source-owned actual phase/actor/source/effect construction of their
own. A later cookie write cannot be relabeled as creation output or explained by
this first snapshot. TLS indices/vectors/templates have a distinct documented
native-output relation; this proposal supplies neither that relation nor its
implementation. Full event/descendant/stream/kernel-termination/compile/link/
load/B/runtime/Linux and product-installer closure remain owed.

The process EXIT event is also not kernel shutdown completion. The complete
controller must create and retain a real independent process-handle duplicate
before terminal continuation, then observe actual native signal after successful
ContinueDebugEvent. API-owned debug process/thread handles are system-retired at
their documented continuation; returned creator handles and held duplicates
retain independent access/inheritance/clock/lifetime and one-use closes. No
double-close, exit-event-as-signal or root-only completion is selected here.

## Required review cases and option B

Future meaningful source regressions must deny attach-shaped/replayed/foreign
events; wrong creator/process/thread/principal/parent/source; prior continuation;
foreign phase; missing actor exclusion; unqualified initial module/source case;
missing/invalid load-config pointer/slot; alias/relocation/IAT/TLS/control overlap;
capacity exhaustion; short/failed/uncertain/native-changed/readback mismatch;
late original clocks; absent last borrower; and later CRT/LOAD_DLL mutation
misclassified as initial output. Synthetic denial/layout cases do not fabricate
genuine creation or qualify a positive native occurrence. Actual positive source
and full native qualification are still mandatory after complete review/admission.

Option B would demand independent entropy/write-history interception before the
first event. The selected user-mode debugger API does not expose that history.
A genuinely different, source-qualified interception/creation mechanism would
need its own kernel/loader/writer source, all new acquisition/trace/capacity/
lifetime costs and possibly a new privileged host boundary. No available event
trace is asserted to expose those bytes. This larger unselected mechanism would
not make cookie entropy source authority and is not silently introduced. Option
A preserves the existing native-output/actor/source contract without predicting
entropy; its exact bounded fit is what the fresh intent review must assess.

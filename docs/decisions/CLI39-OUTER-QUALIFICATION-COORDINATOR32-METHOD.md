# Fixed outer CLI qualification coordinator proposal32

Prospective source proposal for parent architecture disposition. No execution,
new issuer, runtime qualification, source GO or new protocol grant is selected
by this document. Existing official host/distribution trust and complete
installed/loaded closure are the finite foundation, not recursive reproduction
of the coordinator, compiler or verifier.

## Concrete outer owner and finite foundation

Add source-owned `scripts/prerequisite-coordinator32.ps1`, a fixed qualification
entry for one of the existing six actions. It runs in the independently admitted
official PowerShell/.NET qualification host. Its complete startup, interpreter,
CLR, initial stack/TLS, imports and retained overlap belong to the genuine
external qualification operation profile before first statement. The parsed
input never funds its own reader or bootstrap. Missing genuine profile or tool
trust remains unqualified; no extra coordinator is recursively required to
reproduce the admitted official host.

The coordinator first enrolls a minimal receiver/owner and all source/recipe
partials, then imports the same selected shared native owner and initializes
its fixed ABI/sink recipes. It is the actual outer owner before CLI caller
birth. It uses the existing `New-OwnedPrerequisitePreparation` and
`Invoke-OwnedNativeProducerTool` with the literal
`cli39.source-input-host.v1` consumer, current shared ABI, exact original
deadline/response, and genuine outer reservation. There is no Process.Start,
second Job owner, generic callback or compiler/build-host action.

The outer source must consume a separately admitted fixed qualification input
containing complete source/tool/OS/store/policy/profile/namespace facts and
their concrete provenance. Root digest selects its exact bytes; it is not
their authority. The fixed reader must keep the actual held members and native
observations and construct local original associations. This proposal does not
turn an arbitrary JSON object, trusted=true field or digest into permission.

## Actual birth and derived root association

The coordinator captures its own actual process birth/image/principal and
source/loaded/namespace originals before creating the retained caller. The
shared producer owns actual CreateProcess output handles/PID, Job membership,
stdout/stderr capture, original command/environment/cwd/home and control peer.
Those originals remain in its preparation.nativeState through child exit,
tree join, EOF and receiver closure. They are never serialized as CLR pointers.

A concrete source-bound derived-root constructor is needed because child PID
and creation time cannot be predeclared as static input facts before birth.
Before issuing a child, the current parent can create exactly one immutable
held role-specific input root containing the admitted static foundation pins,
its actual parent birth/principal observations and lineage to the admitted
qualification input. The child records its own actual birth locally. The
shared parent owner retains the actual child birth and joins it externally;
the child does not treat a copied expected-child PID as an issuer. Root file
creation, byte count/hash, immutable/exclusive held identity, precharge and
all partial write/hash/disposal paths must be part of this fixed constructor.

The same pattern applies to retained-caller -> operation-host. Each local
constructor binds same-process reference identity only. Across processes it
binds exact held input bytes/lineage and actual native parent/child/control
relations. No local ReferenceEquals check is used as cross-process transport.

This derived-root producer relation requires parent selection before source
implementation: it replaces currently absent producer code, rather than
assuming the existing 29-field decoder already authenticates startupClosure.
The admitted outer command must explicitly cover these fixed derived-root and
child invocations; it cannot silently expand one action into six.

## Peer joins and unchanged control frames

Keep NPH1/NPR1/NPA1/NPD1/NPE1 bytes and semantics unchanged. Each child already
observes the connected server's actual client PID through fixed own13
GetNamedPipeClientProcessId. Join that PID to the parent's actual birth and
principal carried in the source-owned derived root and independently retained
by the real parent owner. Token equality remains routing/challenge identity,
not capability. Parent process/Job handles are actual native originals.

Before useful dispatch, local source/loaded/namespace/principal/allocation
associations must be complete under the admitted foundation and actual held
observations. The capability association is the existing admitted bounded
qualification action plus actual same controlling parent/receiver/command,
not a newly minted token. If a child-side expected parent birth/principal
query is missing, add a fixed source-owned native observation; do not infer it
from PID equality alone.

## Source interfaces and lifetime

Proposed fixed functions are a qualification-root reader, an outer association
constructor, a role-specific immutable derived-root constructor, and one
coordinator invocation function. Their inputs are only actual enrolled reader/
observation originals and the selected six-action role, not effect callbacks.
The existing caller/action functions then consume the actual constructed
admittedInputOriginal/admittedConsumerOriginal/reservations instead of nulls.

Current shared native producer already retains actual nativeState and uses the
closed cli39.source-input-host.v1 slot. No new Core protocol/action selector is
presently identified. Core owner should assess whether its exact native birth/
control originals are available at the needed parent join points. If a fixed
pre-dispatch observation is required while the producer is pending, propose
that specific typed source relation before editing shared code; never add a
generic callback hook or expose raw native grants.

All constructor failure, pre-NPH stall, unknown native return, deadline expiry,
partial raw capture and failed derived-root outputs remain held by the same
outer owner. Deadline response only notifies. No kill/retry/deadline widening
or guessed safe cleanup is introduced. NPD1 closes qualified physical borrows;
resident module/CLR graphs remain charged until actual external host exit.

Whole native/producer profiles, authentic missing OS/store/policy facts and
Windows/Linux full product delivery remain outstanding. This is a bounded
source architecture proposal, not evidence those inputs already exist.

## One lifetime, two acquisition times

The parent creates the target canonical physical owner before native child birth. Its original image, initial stack, TLS/loader/control and inherited runtime backing reservations already include every simultaneously retained original prefix byte and alias. Reservations are page-rounded from the complete qualified source/native geometry before effects; an unknown bound cannot be replaced by zero or a guessed reserve. The target owner storage and parent-side capture/transport copies themselves remain charged to the actual containing parent image/arena. No parent runtime whole-view is created.

The runtime backing is created before child birth under its original target request, progresses RESERVED -> BACKING_ACQUIRED immediately after actual backing creation and before fallible diagnostics, and remains physically charged across export. Child mapping promotes that SAME request. Image/initial stack/TLS/loader prefix reservations also cross birth without another prepare or retirement; the actual native prefix independently observes and promotes each SAME original reservation before normal bootstrap decoding. A reservation with no successful observation stays charged, including failed child birth, partial loader work and failed imports. Actual containing-image storage covers the complete raw ingress, prefix import capture, full immutable decode, working owner, machine-code/import tables, stack and TLS used by that earliest route. No local static declaration creates a free prefix.

The bootstrap arena in bootstrap.c is a **genuine new postbirth acquisition**. It is not a second reservation for a prebirth bootstrap arena: no such arena is prepared by the parent. After prefix reconstruction and normal decoded transport admission, slcli_node_bootstrap_acquire_original calls slcli_platform_acquire on the SAME continued target owner to prepare and acquire a distinct new runtime extent, retaining the original native capture. The transported bootstrap_bytes is the requested new arena geometry, not proof of prebirth backing. Its concurrent physical cost must fit the same owner limit alongside all already reserved/live prefix and runtime costs. Failure retains its new prepared/partial extent. A future conversion to a precreated bootstrap section would require carrying its distinct original request and SAME promotion, and changing the entire constructor consistently; it cannot reuse the runtime request or silently reinterpret this lifetime.

## Required earliest native sequence

1. The selected real kernel/loader entry runs the qualified prefix before original CRT/libc initialization, retaining original entry stack/auxv and platform continuation. Windows includes preentry TLS/import/cookie/helper effects; Linux includes the selected actual loader/startup route. Every executed instruction, static/capture byte and native attempt belongs to the already precharged source-native prefix. Entry location alone does not prove private writer exclusion, parent/source/caller or image association.
2. The prefix independently joins the original native child birth, selected image/source/entry, original parent and actual private transport backing/range, rights and complete writer exclusion. Preserve raw native observations and failures in the paid prefix capture. Neither a PID, matching byte digest, handle comparison, raw parent pointer nor a supplied boolean grants this authority. The Linux pre-exec birth publication is a real parent observation but does not replace the new image's own native join.
3. Acquire and retain the exact finite raw transport in paid immutable ingress storage. Validate its framing/ABI and canonical owner encoding without using foreign pointers as child addresses. The full original frozen owner is structural evidence of an existing charge, not native authority. An early import capture must be distinct from the normal one-use image_transport decode capture; both real copies remain charged. Do not erase/reuse either capture on failure. The complete source-derived inventory must count these copies and their actual stack/codegen temporaries.
4. Continue the exact once canonical frozen owner into fresh child-local working-owner storage. Independently match the full original associations/frontier and original requests to the real native image, initial stack, TLS/loader/control and ingress extents. Promote each original prefix request to the actual observed local address/geometry with no new prepare; retain unknown/partial native outputs under their original request. Actual mappings must not overlap contrary to their true physical alias relation. The raw ingress and all decoder/import storage must now be demonstrably covered by these live prefix extents. The private prefix performs this reconstruction before calling the public normal decoder; it does not weaken image_charged/input_charged or call a later main-time substitute.
5. Call the unchanged guarded normal transport decoder. It retains complete raw bytes, immutable decoded owner and separate working/decoder storage under actual owners. Verify normal decoded transport against the exact frozen predecessor and already continued working owner; never initialize a fresh quota, continue twice or treat an independent owner with equal fields as the original lineage.
6. Acquire the distinct postbirth bootstrap arena on that continued owner. Copy only local charged caller/deadline/native expected/request inputs into it. Receive the inherited runtime backing and map its SAME original BACKING_ACQUIRED request. Keep the original section/FD/handle observations, expected original object identity, native mapping geometry, partial outputs and zero-address disposition. The normal allocator binds only after complete source-native admission, identity and mapping checks.
7. Continue the original genuine CRT/libc/Node startup with ordinary full behavior. Failures retain all canonical physical charges and actual parent/child captures until separately witnessed terminal disposition; no fake early retirement or gate-time mutation of the parent's frozen ledger occurs.

# Fixed same-process qualification startup handoff proposal

Status: architecture proposal only; current source does not supply the admitted startup original. No new issuer, authority record, execution or recursive host qualification is proposed.

## Actual source gap

Current prerequisite-qualification32.ps1 calls New-Cli39QualificationCoordinator32 with metadata only. That factory constructs a fresh receiver and host-control record. Neither can retain a preexisting admitted startup reservation/native owner. Existing CLI caller32 requires an already admitted CLI root and therefore cannot bootstrap qualification. Core windows-native-producer-caller.ps1 Invoke-OwnedNativeProducerInvocation (whole file read) accepts Abi/Receiver/InputRoot/Reservation/deadline and dispatches only the fixed Core compile host; it is not a CLI qualification caller. Core build grammar/reservation must not become CLI input. No existing concrete source callsite constructs a qualified CLI startup original.

## Smallest fixed caller path

Add a source-only module prerequisite-qualification-caller32.ps1 exposing Invoke-Cli39QualificationFromStartup32. It consumes the SAME already-admitted official-host startup original, SAME receiver and SAME CLI startup reservation/deadline by local CLR references. It calls New-Cli39QualificationCoordinator32 directly in that process; it does not start another process, import a supplied script, accept a callback, grant a capability from a map or manufacture an admission receipt. Its exact action/root/static invocation pins are the selected CLI input, separate from the official-host foundation.

The actual startup original must be the existing containing official host owner, with retained actual host process/lifetime, source-native entry/deadline response, genuine startup allocation reservation and source/tool/installed/loaded foundation originals. This proposal does not assert that any current dictionary has those properties. Current shared owner hostOwnerOriginal gives a concrete identity/receiver/deadline holder, but the current source contains no genuine qualification of its own initial startup. Those authentic facts remain external finite foundation input obligations, not code-created trust.

Change coordinator signature to require HostOwnerOriginal and StartupReservationOriginal, in addition to exact root metadata/action. Reuse the actual host's existing receiver/key/originalDeadlineTicks/deadlineResponse and already enrolled pre-NPH ABI/sink/namespace/principal/parent recipes. Require actual inputRead.value and consumerOriginal absent: this fixed entry consumes a host prepared specifically for CLI qualification, never overwrites a Core or existing CLI root. Keep current inputRead/consumer/root association enrollment on that SAME host. Preserve the containing startup original/reservation as actual references; do not allocate a substitute receiver or call its own successful initializer an authentication witness.

The caller must bind StartupReservationOriginal to the existing startup owner and exact CLI invocation before the root reader's first allocation. Actual field names/types cannot be invented from current metadata: source still needs the selected official-host foundation's concrete original representation. Existing shared preparation has receiver/reservation/consumerOriginal/originalDeadlineTicks/deadlineResponse/nativeState; nativeState represents a child operation and must not be relabeled as the containing host's own startup. A proposed adapter may retain such an actual externally admitted startup original but may not substitute preparation.nativeState of a different child.

Lifetime: the original containing host remains retained across root read, derived-root creation, both child births, all six actual consumers, failure cleanup and actual receiver/host exit. Startup reservation stays charged through actual external host join. Original deadline notification never stops workers or retires resources. Constructor/parse/import/worker failures retain the same outer original. Caller/entry records retain raw attempts/errors independently; no future external issuer/file count is needed.

## Disposition requested

Select the smallest fixed caller/signature handoff and identify the actual existing official-host startup original representation if one is selected elsewhere. If none exists, the source gap is specifically its fixed containing-host startup constructor/adapter, not another root hash or receipt. The implementation must fill that fixed source path while genuine native/installed/profile values remain unknown until full source/input qualification. No generic startup authority hashtable, Core compile-lane reuse, cross-process CLR identity transport or recursive reproduction is selected.

# CLI39 production deadline construction proposal

Status: PROPOSED, NOT ADOPTED. This is the whole initial-interval design question for the existing selected19/67 constructor scope, not a new timeout policy, implementation approval or execution admission. No numeric production interval is selected here.

## Existing authority and the concrete gap

Selected19 DESIGN150 requires original closed LAUNCH, lexical caller-cwd resolution once, authenticated service reservation before observer/primary birth, and prebinding before START. Selected67 DESIGN47/51/53/55/81 requires one immutable original caller/origin/expiry/predecessor throughout native effects and publication. Selected67 DESIGN158 explicitly makes qualification10/10/10/20 absolute40 qualification-specific and forbids a new universal production40. SPEC-CLI-FOUNDATION source65 also requires the independently supplied private original caller deadline without universal40.

Current library-transport.ts creates performance.now()+40000 and a40000 timer in its private constructor; open/launch take no finite caller interval, and launch encodes no deadline. Scoped current callers do not connect this helper to the public ordinary native route. The ordinary scaffold options preserve id/directory/name/templateRoot/dryRun and have no native operation interval. Core operation waitMs polling is a different post-submission operation and clock. These are scoped current source observations, not a repo-wide absence proof or authority to transplant a JavaScript clock/number into the native origin.

Actual Windows suspended native birth and Linux gated clone/held-fd exec constructors now consume an existing immutable original native deadline. They do not solve initial interval selection, caller/source admission, native preentry or complete installed delivery by themselves.

## Proposed complete construction rule

The originating native facade/launcher captures its actual native process/thread/birth and monotonic start under the selected command contract, before the child CRT. It constructs the sole original deadline once using a finite production interval selected through an explicitly adopted policy/input path. Checked nanosecond conversion and addition must reject zero, overflow and unsupported native wait geometry before child effects. An original relative interval is request data; it cannot designate source, provider, actor, ROOT, catalogue, executable or native authority.

The same origin/absolute expiry is carried through genuine inherited preentry backing/descriptor association, full Node owner/caller attachment, LAUNCH/service reservation, observer/primary/SEA/writer, ledger/receipt/archive/ACK and final result. No JS performance.now/Date.now value is accepted as the native clock. No child, reconnect, nested operation, allocator, wait, cancellation, completion or publication can start a new budget. Wall-clock/native scheduling overrun is an actual retained failed qualification; a kernel timeout is not a hard scheduler proof.

The receiver must independently join actual parent/child birth, held inherited descriptors and backing identity, private transport/capability, source image and the selected original caller. Routing fields/argv/environment are not that join. Loader/CRT/static/TLS original extents and whole measured B0/B2 remain independently required; late mapping/RSS observations cannot manufacture historical preentry ownership.

## Whole alternatives and compatibility

A. Preserve existing no-timeout CLI/library calls through an adopted source-owned finite operation-specific default policy. The actual original command selects its own closed operation policy, embedded in the qualified immutable source/image profile and available before child CRT. An optional explicit caller interval is selected only at originating construction and may be shorter or longer than the default if representable by the actual native route; no expiry mutation after construction. This preserves existing signatures/default invocation behavior, but requires adoption of actual per-operation values and their whole-runtime/native qualification. This proposal supplies no such numeric values and cannot derive them from qualification40 or measured memory.

B. Require an explicit finite original caller interval for every native command, carried unchanged. Public CLI/library signatures must state the interval and origin semantics. Existing no-timeout calls would need an explicit versioned migration or a separately adopted compatibility policy; silently denying all old ordinary callers is not delivery of the selected useful default route. A JavaScript wrapper can request an interval, but the native original launcher owns the real clock and immutable expiry. Explicit input supplies no external authority. No arbitrary frontend maximum is invented here.

C. Combine A and B: optional explicit finite caller interval with an adopted operation-specific native default for unchanged callers. This is the preferred compatibility shape to evaluate, not adopted policy. Parsing occurs in the actual original native launcher before child birth, using its charged original argument storage; it must not renew a deadline after full Node startup. Library binding must carry the original request to that launcher without borrowing the unrelated Core waitMs option. Unknown/malformed/out-of-range input denies before birth and preserves original diagnostics/captures.

All alternatives must retain ordinary complete full Node/default-thread/facade/SEA/library behavior and selected privacy/input preservation/native lifecycle, with actual Win/Linux evidence. None permits an unbounded default, silent global40, reduced runtime, missing-origin Boolean, caller-issued authority certificate or metadata-only preentry proof.

No target execution follows from this proposal; separate entire SOURCE_GO, authentic new complete INPUTROOT and parent exact command admission remain unchanged. Complete original G1–G8/selected19+67, measured whole B0/B2, runtime128/physical256/retained128, operator/publication/Core samebytes requirements survive.

These three proposals deliberately select full top-level operations before birth. READ/PLAN/CLOSE phases, callbacks, default Node threads, ACK and later disposal do not receive separate budgets. No source build/compiler/package work is charged to an ordinary command by silently extending these intervals. Existing operations that only return metadata preview do not start a fake native session to obtain a deadline. A library operation that later materializes must select the materialization original operation at the originating launcher; inspection completion cannot renew its deadline into a writer session.

Proposed request form is an optional finite positive integral millisecond interval, represented natively with checked uint64 nanosecond conversion. At original construction an explicitly supplied finite request may be shorter or longer than the selected operation default; absent input chooses that operation's adopted source default. DEFAULT is not a maximum. Selecting a longer original interval before birth does not renew an already constructed deadline. Zero, fractional, negative, overflowed or actually unrepresentable native/protocol geometry fails before child birth with its original input/diagnostic retained. There is no new frontend/product maximum inferred from this default table; native representability checks must trace the actual selected API/wire width, sentinel and conversion constraints. An independently adopted maximum would require its own concrete contract rationale and is not proposed here. Default values and explicit input representation must be reviewed together as a whole compatibility amendment; no new public argument/wire member is implemented here. The interval remains request data and never caller/source/issuer/native admission.

Public compatibility proposal: existing CLI invocations and existing library calls without the new optional field retain their full ordinary operation behavior using the matching adopted source default. An optional CLI `--operation-timeout-ms` and library option `operationTimeoutMs` would affect native authoring only, never unrelated Core `waitMs` or lifecycle/request cancellation. The exact names, exported overloads and closed private LAUNCH grammar require coordinated review; existing fixed READ/PLAN/CLOSE codes and packet caps survive. This table cannot substitute for actual full Windows/Linux source/native fixture qualification, late-effect retention, measured B0/B2, original caller/source/authentication or parent exact execution admission.
